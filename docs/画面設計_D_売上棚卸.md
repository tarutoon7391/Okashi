# 画面設計（担当D：売上・棚卸）お手本　コマ3

## SC-30 売上入力　sales/sales_input.php　（権限：ログイン済）

### 入力項目
| 項目 | name | 型 | 必須 | 初期値 | チェック |
|---|---|---|---|---|---|
| 売上日 | sales_date | date | ○ | 今日 | 変更したら GET で再表示 |
| 売上数（商品ごと） | sales_qty[商品コード] | number | | 同じ売上日に登録済みの数量 | 整数。空・0の商品は登録しない |

### 表示項目
商品一覧（**is_deleted=0、商品名カナ昇順**）：商品コード・商品名（保存区分バッジ）・規格・定価・登録済数量・売上金額（定価×数量）・状態（未確定／確定済）・合計

### ボタンと遷移
| ボタン | 動作 | 遷移先 |
|---|---|---|
| この日の売上を表示 | GET で再表示 | SC-30 |
| 登録 | 上書き登録（下の注意） | SC-30（完了メッセージ） |
| メニューへ戻る | | SC-01 |

### 注意（質問No.8：同一日・同一商品は上書き）
- 未確定の行がある → その行の sales_qty・amount を UPDATE
- 確定済みの行しか無い → 差分（入力値 − 確定済み合計）を訂正行として INSERT（確定済み行は書き換えない）
- amount = m_product.list_price × sales_qty を保存

## SC-31 売上確定　sales/sales_confirm.php　（権限：ログイン済）

### 入力項目
| 項目 | name | 型 | 必須 |
|---|---|---|---|
| 確定する売上日 | sales_date[] | checkbox | 1件以上 |

### 表示項目
未確定の売上を**売上日ごとにまとめた**一覧：売上日・件数（商品数）・合計数量・合計金額・状態（.status-unconfirmed）

### ボタンと遷移
| ボタン | 動作 | 遷移先 |
|---|---|---|
| 確定（.btn-danger・confirmSubmit） | 選んだ日付の未確定行を1行ずつ confirmSales()（在庫が減る） | SC-31（完了メッセージ） |
| メニューへ戻る | | SC-01 |

## SC-40 棚卸入力　stocktaking/stocktaking_input.php　（権限：ログイン済）

### 入力項目
| 項目 | name | 型 | 必須 | 初期値 | チェック |
|---|---|---|---|---|---|
| 検索：商品コード | product_code | text | | 空 | 部分一致 |
| 検索：商品名 | product_name | text | | 空 | 部分一致 |
| 棚卸日 | stocktaking_date | date | ○ | 今日 | |
| 実数（商品ごと） | actual_qty[商品コード] | number | | 空 | 0以上の整数。空の行は処理しない |
| 差異の原因・理由 | reason[商品コード] | text | **差異がある行だけ○** | 空 | 200文字以内 |

### 表示項目
全商品一覧（検索時は該当商品のみ・カナ昇順）：商品コード・商品名（保存区分バッジ）・規格・現在庫・差異（実数−現在庫、JSで自動計算）
- 在庫が0以下の行は **.stock-warning**（赤背景）

### ボタンと遷移
| ボタン | 動作 | 遷移先 |
|---|---|---|
| 検索／全商品を表示 | GET で再表示 | SC-40 |
| 在庫を更新（.btn-danger・confirmSubmit） | 実数が入った行ごとに applyStocktaking(商品コード, 実数, 理由)。差異0は記録しない | SC-40（完了メッセージ） |
| メニューへ戻る | | SC-01 |

### 注意
- 理由が抜けている行があれば1件も更新せず、入力値を残して画面に戻す
- 在庫の上書きは applyStocktaking() が行う。t_stock を自分で UPDATE しない
