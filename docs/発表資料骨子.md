# 発表資料の骨子（SE コマ9 作成 → コマ10 で完成）

1. **システム概要**（SE・1枚）
   - お土産屋さんの発注〜納品〜在庫〜売上を1つにまとめたWebシステム
   - 解決したこと（要件定義書の「現状の問題点」に対応させる）
     - 発注・納品の状況が一目で分かる（未納品一覧、状態の色分け）
     - キャンセル・訂正はマイナス伝票で履歴が残る
     - 在庫は納品確定・売上確定・棚卸の3か所だけで動く（食い違いを防ぐ）
2. **体制とスケジュール**（SE・1枚）：SE＋担当A〜E、全11コマ。コマごとの計画と実績
3. **設計の工夫**（SE・1〜2枚）
   - 命名規則を先に決めて全員で統一（テーブル m_/t_、ファイル <業務>_<動作>.php）
   - 在庫更新を common/slip.php に集約、確定済み伝票は書き換えない
   - 質問書14項目の回答を設計書に反映（返品＝納品のマイナス伝票、二要素認証 など）
   - GitHub（PRと自動チェック）＋ Railway（自動デプロイ）で開発
4. **画面デモ**（全員）：docs/デモシナリオ.md の順
5. **テスト結果**（E・1枚）：ケース数・OK率・見つかった主なバグと対応
6. **担当ごとの発表**（各自）：担当作業・苦労した点・所感①（設計書）・所感②（リーダー／課員）
7. **今後の課題**（SE）：独自ドメインでのメール送信、賞味期限アラート、権限の細分化 など
