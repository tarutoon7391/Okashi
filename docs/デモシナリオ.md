# デモシナリオ（SE コマ10 作成・発表で使う）

所要 8〜10 分。本番URL（Railway）で行う。事前に `SEED_TEST_DATA=1` でテストデータを入れた状態にしておく。
各パートはその担当者が画面を操作しながら説明する。

| # | 担当 | 操作 | 見せるポイント |
|---|---|---|---|
| 1 | SE | OP001 でログイン → ワンタイムコード入力 | 二要素認証（質問No.10）。メールでコードが届く |
| 2 | SE | OP002 でもログインして見せる（別ブラウザ） | 承認不可だと「発注確定」が出ない・URL直打ちでも弾かれる（質問No.5） |
| 3 | A | 商品マスタで「テスト最中 5個入（冷蔵）」を登録 | カナ順の一覧、冷蔵バッジ、入数違いは別コード（質問No.1・12） |
| 4 | B | 発注入力：新商品と別卸業者の商品を1回で入力 | 商品コードを入れると商品情報と金額が出る。卸業者ごとに伝票が分かれる |
| 5 | B | マイナス数量で取消（取消元を選ぶ） | 赤字表示。訂正はマイナス伝票（質問No.3） |
| 6 | B | 発注確定 → 発注書PDF・検品一覧表PDF | 確定後は変更不可。卸業者へ発注書PDFをメール送信（質問No.6） |
| 7 | C | 納品入力：一部だけ納品 → 納品確定 | 残数が減る。確定で在庫が増える |
| 8 | C | 返品伝票 → 納品確定 | 返品は納品のマイナス伝票（質問No.4）。紫の行で区別 |
| 9 | C | 未納品一覧表（PDF） | 取消・納品を差し引いた残数 |
| 10 | D | 売上入力 → 同じ日にもう一度入力 → 売上確定 | 上書き（質問No.8）。確定で在庫が減る |
| 11 | D | 棚卸：実数と理由を入れる | 在庫が実数に。棚卸調整一覧表に記録 |
| 12 | E | 発注明細表・集計、卸業者別納品金額（円グラフ） | 絞り込み・マイナス込みの合計・表とグラフが一致 |
| 13 | E | テスト結果（ケース数・OK率・主なバグ） | テスト仕様書の集計 |

## 失敗したときの保険
- メールが届かない → Railway の Variables で `MAIL_DRIVER=log` にして Redeploy（コードが画面に出る）
- データが崩れた → MySQL のテーブルを消して Redeploy（テストデータから作り直し。1〜2分）
- ネットが無い → ローカル（`start_local.bat reset`）で同じシナリオ
