# 結合手順書（SE コマ7 作成 → コマ8 で使う）

コマ8の前半30分で「全員のファイルを1つの環境に集めて、発注→納品→在庫→売上が通る」ところまで行く。
GitHub で開発しているので、**配置 = main へのマージ**、**結合環境 = ローカル（start_local.bat）と Railway 本番**の2つ。

## 0. 前日まで（コマ7の最後）
- 全員：自分のブランチをプッシュして PR を出しておく（GitHub の自動チェックが緑になっていること）
- SE：画面一覧（02）と PR のファイルを突き合わせる（無いファイル・余計なファイルが無いか）

## 1. マージの順番（依存の親から）
| 順 | 担当 | 中身 | マージ後に確認すること |
|---|---|---|---|
| 1 | A | common/（config・db・functions・header・footer・pdf・query・report）、sql/01・02、css、js/common.js | `start_local.bat reset` でテーブルと初期データができる |
| 2 | SE | common/auth・slip・mail、index・otp_input・logout・menu | OP001 でログイン → メニューが出る。OP002 だと発注確定が出ない |
| 3 | A | master/ | 商品・卸業者・操作者の一覧・登録・削除 |
| 4 | B | order/、js/order_input.js | 発注入力 → 発注確定 → 発注書PDF |
| 5 | C | delivery/、return_goods/、js/delivery_input.js | 納品入力 → 納品確定で在庫が増える → 未納品一覧表 |
| 6 | D | sales/、stocktaking/、report/sales_*・stocktaking_list | 売上入力 → 売上確定で在庫が減る → 棚卸 |
| 7 | E | report/ 残り、js/supplier_summary.js、sql/03、docs/テスト仕様書.xlsx | 明細表・集計・円グラフ |

マージは SE が GitHub の画面で行う。コンフリクトしたら、そのファイルの担当者と SE で直す（他人のファイルは触らない）。

## 2. データの流し方
- ローカル：`start_local.bat reset`（sql/01 → 02 → 03 を流し直す）
- Railway：MySQL サービスの Data タブで全テーブルを削除 → web サービスを Redeploy（起動時に自動で流れる。`SEED_TEST_DATA=1` なら 03 も）

## 3. 通しの確認（この順で。止まったらその担当に振る）
1. ログイン（OP001 / pass1234 → ワンタイムコード）
2. 商品マスタに1件登録（在庫0で作られる）
3. 発注入力：2つの卸業者の商品を1回で登録 → 伝票が2枚できる
4. 発注確定 → 発注書PDF・検品一覧表PDF・メール（mailed_at）
5. 納品入力：一部納品 → 納品確定 → 在庫が増える → 未納品一覧表に残数
6. 返品伝票 → 納品確定 → 在庫が減る
7. 売上入力 → 売上確定 → 在庫が減る
8. 棚卸：実数を入れる → 在庫が実数になる
9. 明細表・集計・卸業者別納品金額で数字が合う
10. `php tools/slip_test.php`（在庫更新の自動テスト）が「すべてOK」

## 4. バグが出たら
E のバグ票（docs/テスト仕様書.xlsx「バグ票」シート）に「画面ID・操作・期待・実際・担当」を1行で書き、担当者に口頭で伝える。
直したら PR → マージ → E が再テスト。
